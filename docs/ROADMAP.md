# CurvG 路线图

更新时间：2026-07-22

## Phase 0 — 项目初始化

状态：已完成

- 品牌、域名、双语 metadata、Logo、首页视觉系统。
- 公式驱动的静态曲线预览。
- 早期访问入口和诚实的能力边界。
- Cloudflare 目标架构与研发文档。

## Phase 1 — 动态曲线画廊

目标：先做不依赖 AI 和视频渲染也有价值的内容产品。

- 新增曲线、标签、参数和公开状态数据表。
- 建立画廊列表、详情页、公式参数编辑和分享 URL。
- 浏览器端实时 SVG/Canvas 预览。
- 管理后台发布、排序和 SEO 字段管理。
- 首批 30–50 个经过人工检查的曲线条目。

验收标准：未登录用户可以搜索、筛选、查看公式并调整参数。

## Phase 2 — AI 场景规划

目标：把用户意图转成可检查的结构化计划，不直接渲染。

- 设计公式和场景计划 Zod schema。
- 新增生成 API、任务记录和积分预扣/撤销。
- 输出镜头、时间轴、标签、颜色、相机和候选 Manim 代码。
- 增加人工确认步骤和版本历史。
- 建立数学错误反馈与回放数据。

验收标准：同一输入可复现生成记录，用户能在渲染前修改计划和代码。

## Phase 3 — Cloudflare Sandbox 渲染

目标：安全执行确认后的 Manim 场景。

- 验证 Sandbox 对镜像、依赖、并发、超时、网络和文件输出的实际限制。
- 完成 D1 任务状态机、重试和幂等回调。
- 将源码、日志、缩略图和视频写入 R2。
- 实现预览质量与最终质量两档渲染。
- 增加资源配额、恶意代码检测和失败诊断。

验收标准：代表性场景成功率、P95 渲染时间和单位成本达到预设阈值。

## Phase 4 — 产品化与计费

目标：在成本数据基础上发布套餐，而不是先猜价格。

- 汇总至少 50–100 个真实场景成本样本。
- 定义积分单位、并发限制、存储保留期和失败退款规则。
- 接入支付套餐和 Webhook。
- 增加作品私有/公开、下载权限和删除策略。
- 完成隐私政策、服务条款和内容审核规则的产品化修订。

## 当前最优先的下一步

更新时间：2026-08-01（依据生产 Cloudflare 部署与 `curvg-db` 实测数据修正）

Phase 2 与 Phase 3 已实现并部署，生产跑出 46 条 completed 阶段与 30 条动画记录。
风险敞口从「未验证」转移到「交付质量」：

1. **P0：降低确定性兜底占比。** 2026-07-31 有 71% 的 completed 阶段由
   `provider=curvg` 的预置场景替代产出（前一天 32%），用户看到成功但拿到与
   prompt 无关的内容。这是当前最大的产品风险，且完成率指标看不出来。
2. **P0：修复主模型可用性。** 阶段表记录 `kuaipao` 89 次对 `kie` 12 次，指定主
   模型 KIE 实际在大部分时候失败，由恢复路由静默承担。需要补按次尝试的埋点，
   否则无法度量。
3. **P0：把 Python 产出收归编译器。** `composeAnimationCode` 当前让模型写 14k
   token 的 Python，编译器只是兜底——与 `CREATOR_REQUIREMENTS.md` 五节的决策
   相反。这一处同时是超时、workflow 预算耗尽和质量波动的共同来源。
4. **P1：采集真实成本数据**——记录 10–50 个场景的渲染成本，作为定价前提。
5. **P1：`/curves` 曲线百科 + 画廊页面**——画廊目前只有 API 路由，没有页面，
   生产 0 条已发布。SEO 是时间函数，越早发布越早生效。
6. **P2：SymPy 数学验证 + 参数化模板库**——建立 "verified math" 差异化。

详细的信息架构、双层内容结构（百科 + 画廊）与各页面验收标准见 `docs/SITE_ARCHITECTURE_PLAN.md`。
