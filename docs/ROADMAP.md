## Phase 2 — AI 场景规划

目标：把用户意图转成可检查的结构化计划，不直接渲染。

- 设计公式和场景计划 Zod schema。
- 新增生成 API、任务记录和积分预扣/撤销。
- 输出镜头、时间轴、标签、颜色、相机和候选 Manim 代码。
- 增加人工确认步骤和版本历史。
- 建立数学错误反馈与回放数据。

验收标准：同一输入可复现生成记录，用户能在渲染前修改计划和代码。

## Phase 3 — Cloudflare Sandbox 渲染

目标：安全执行确认后的 Manim 场景。

- 验证 Sandbox 对镜像、依赖、并发、超时、网络和文件输出的实际限制。
- 完成 D1 任务状态机、重试和幂等回调。
- 将源码、日志、缩略图和视频写入 R2。
- 实现预览质量与最终质量两档渲染。
- 增加资源配额、恶意代码检测和失败诊断。

验收标准：代表性场景成功率、P95 渲染时间和单位成本达到预设阈值。

## Phase 4 — 产品化与计费

目标：在成本数据基础上发布套餐，而不是先猜价格。

- 汇总至少 50–100 个真实场景成本样本。
- 定义积分单位、并发限制、存储保留期和失败退款规则。
- 接入支付套餐和 Webhook。
- 增加作品私有/公开、下载权限和删除策略。
- 完成隐私政策、服务条款和内容审核规则的产品化修订。

## 当前最优先的下一步

更新时间：2026-08-01（依据生产 Cloudflare 部署与 `curvg-db` 实测数据修正）

Phase 2 与 Phase 3 已实现并部署，生产跑出 46 条 completed 阶段与 30 条动画记录。
风险敞口从「未验证」转移到「交付质量」：

1. **P0：验证 scene-only 恢复的交付质量。** 2026-07-31 有 71% 的 completed
   阶段由旧的 `provider=curvg` 预置场景替代产出，用户看到成功但拿到与 prompt
   无关的内容。当前实现只允许 scene 阶段在前五个 artifacts 已批准后做基于谱系
   的保守恢复；需要用 `diagnostic.kind=deterministic_scene_fallback` 单独统计
   它的成功率、渲染质量和用户重试率。
2. **P0：用按次尝试数据判断 provider 健康。** `animation_planning_attempt` 已
   记录每个 failover leg 的结果。不要从最终 stage 行数推断某个 provider 是否
   失败；应按 stage、模型、错误码、延迟和恢复率持续观测。
3. **P0：把 Python 产出收归编译器（本地已修复，待部署验证）。** 初次出片现在
   由 `compileAnimationSpec` 生成 Python，`composeAnimationCode` 只在有渲染证据
   的定向修复中使用。这是降低超时、Workflow 预算消耗和输出方差的关键改动。
4. **P1：采集真实成本数据**——记录 10–50 个场景的渲染成本，作为定价前提。
5. **P1（部分完成 2026-08-04）：`/curves` 曲线百科已建成**（30 条，含内页矩阵
   与首页 SEO 重定位，见 `docs/CURVE_ENCYCLOPEDIA.md` 与
   `docs/SEO_CONTENT_STRATEGY.md` §0），待部署 + GSC/Bing 提交 sitemap。
   画廊页面仍未实施：只有 API 路由，生产 0 条已发布。
6. **P2：SymPy 数学验证 + 参数化模板库**——建立 "verified math" 差异化。

详细的信息架构、双层内容结构（百科 + 画廊）与各页面验收标准见 `docs/SITE_ARCHITECTURE_PLAN.md`。
