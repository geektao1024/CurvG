# CurvG 交互实验（/labs）规划

更新时间：2026-10-12

## 1. 定位

`/labs` 是 CurvG 的免费交互工具层：一个知识点 = 一块能拖动的画板 + 引导步骤 + 讲解 + 随堂检测。
它承担两件事：

1. **获客**：每个章节页是一个可收录的长尾页，承接「导数的几何意义」「unit circle sine」这类知识点搜索。
2. **转化**：每页都有「做成视频」入口（顶栏 CTA + 文末卡片），把画板的引导步骤作为脚本带进 `/creator`。

表现形式借鉴 wedulab 的实验页（整屏工作台、章节栏、画板叠标题、右侧讲解），但外框是 CurvG 自己的：
左上角是 CurvG 品牌回首页，紧跟面包屑；右上角是「做成视频」和登录 / 账户。不做 wedulab 的独立产品
字标（FUNCLAB 之类）。

## 2. 信息架构与 URL

```text
/labs                              Hub：按学科分组，每个实验集一张卡，卡上列出全部章节
/labs/{suite}                      实验集的第一章（与实验集同一页，避免重复页面）
/labs/{suite}/{chapter}            其余章节
```

- 学科（`LAB_SUBJECTS`）：`math` 已公开；`physics` 已预留为 `draft`，有了实验集后改成 `public` 才会在 Hub 出现。学科不单独占 URL。
- 实验集（`LAB_SUITES`）：`functions`（函数与微积分）、`conics`（圆锥曲线）、`geometry`（几何与证明）。
- 每个公开章节必须且只能属于一个实验集（测试强制）。
- slug 用概念名，学段不进 URL。实验集 slug 不得与章节 slug 相同。
- 旧地址 `/labs/{chapter}` 一律 301 到它在实验集里的新地址；`/labs/{suite}/{第一章}` 301 到 `/labs/{suite}`。

## 4. 预留位

- 讲解视频：见 §4.1。成片发布后由 `labVideo(lab, lang)` 提供，页面自动出现播放器、字幕轨和 `VideoObject`。
- `physics` 学科：只需新增实验集并把学科改成 `public`。
- 新实验集：在 `LAB_SUITES` 加一项即可，Hub、sitemap、llms.txt、面包屑自动跟上。

### 4.1 讲解视频（2026-10-13）

每章的引导步骤就是视频脚本：`title` 是画面标题，`body` 是旁白（行内 TeX 会被转成口语），`set` 是这一步画板要去的参数。

```bash
pnpm dev                                   # 或任何能访问 /render/lab/* 的服务
LAB_VIDEO_TTS=openai LAB_VIDEO_TTS_URL=… LAB_VIDEO_TTS_KEY=… LAB_VIDEO_TTS_MODEL=… \
  LAB_VIDEO_VOICE_ZH=… LAB_VIDEO_VOICE_EN=… \
  pnpm video:labs [--lang zh,en] [--aspect landscape,portrait] [slug …]
pnpm video:labs:publish [--local] [--dry-run] [slug …]   # 上传 R2，更新 videos.generated.ts
```

- 产物在 `output/lab-videos/{slug}/`：`{lang}-{aspect}.mp4`、同名 `.jpg` 封面和 `.json` manifest，以及 `{lang}.vtt`。
- 改了讲解文案要重新渲染：manifest 记录 `labUpdated`，与 `lab.updated` 不一致的成片不会被发布。
- 不设 `LAB_VIDEO_TTS` 时用 macOS 系统语音出草稿，只用来检查时长和版式，发布脚本默认跳过。
- 预览：浏览器打开 `/render/lab/{slug}?lang=zh&aspect=landscape` 会按估算时长循环播放。
- 写讲解时：一句话说一件事，避免在 TeX 里堆复杂结构；`tests/lab-video.test.ts` 会检查所有配音稿和字幕不残留 TeX。

## 5. 新增章节检查表

1. 中英文案齐全；讲解里的数字由「lab guide claims」测试钉住。
2. 可拖动的点放回原处参数不变；答案区间与状态读数一致（edulab 的自检规则，已写成测试）。
3. `updated` 写当天日期。
4. 跑 `node scripts/lab-og-images.mjs` 生成分享图。
5. `pnpm build` 与 lab 测试通过。

### 6.1 写物理章节的约定（2026-10-12）

- 时间用一个带 `play` 的参数（`T`），落地、靠岸等终点用 `min(T, 终点时间)` 截住，保证播放到底停在结果上。
- 角度给学生看的一律用度（`deg`），在 `scalars` 里换成弧度；只有绕固定圆心拖动的点才用弧度参数（`drag.angle`）。
- 表达式没有 `==`、`&&`：用 `abs(x) < 0.001` 判等，用 `(条件1) * (条件2) > 0` 表示"且"。
- 箭头按固定比例画（`k * v`），并用 `min()` 封顶，避免大参数时冲出画板；纯文字标签（`label`）不是 TeX，写 `vy` 而不是 `v_y`。
- 物理章节挂在资源库已有的数学分类上（如 v-t 图 → `rates` / `accumulation`，抛体 → `parametric`），不新开分类。
- 每章在 `tests/labs-content.test.ts` 的 "lab guide claims" 里钉住引导步骤提到的每个数字。
- 线段的 `label` 画在中点：短箭头（力的分量）不要用 `label`，改在箭头末端放一个 `text`，否则标签会压住物体。
- 受力图里各个力按同一比例画（如重力固定画 3 个单位，其余乘 `3 / mg`），分量用虚线，摩擦力从接触面画出。
- 用近似公式的章节（如单摆小角度），同时给出更准确的读数，并用答案区间 + 状态读数标出近似成立的范围。

### 6.2 写数学章节的补充约定（2026-10-13）

- 迭代算法（如二分法）没有循环可用：把每一步展开成标量 `a1, b1 … a10, b10`，第 k 步写成 `n >= k ? 更新 : 上一步`，最后一组就是第 n 步的结果；测试里用普通循环逐步核对。
- 讲解区只支持 `- ` 无序列表，不支持 `1.` 编号列表。
- 结果卡片的公式（`resultTex`）只放一条短式子，太长会在右栏折行；完整结论写在讲解区。
- 第一性原理：画板读数要直接量出定义里的量（如椭圆的 |PF₁| + |PF₂| 用坐标算距离，而不是写死 2a），公式在讲解区由定义推出；只给结论的地方至少补一句理由。
- 多边形默认填充，只想要轮廓时写 `fill: false`。
- 表达式最长 400 个字符：长的求和、连乘拆成几个标量（如二项分布的 C(n,k) 分成前 10 项、后 10 项）。
- 需要随机性的章节（如大数定律）用固定种子预先跑好的模拟记录，作为常数写进章节文件并注明种子；测试用同一种子重跑核对。讲解区要说明这是记录，不是现场随机。
- 没有闭式结果的量（如正态分布的区间概率）用数值积分在画板里算，测试用独立的方法（级数）核对，讲解区说明数是怎么算出来的。
- 默认参数选能看出本章要点的状态（如正弦型默认 A=2、ω=2、φ=60°），分享图就按默认值渲染；第一步引导再回到最简单的情形。
