# WhyCurvG Specification

## Overview

- **Target file:** `src/blocks/why-curvg.tsx`
- **Audience:** 正在判断 CurvG 是否适合其数学讲解或内容创作任务的市场用户
- **Purpose:** 说明 CurvG 带来的两类核心价值：让数学关系更容易理解，让动画创作过程保持可检查、可修改。

## Content structure

- 左侧：价值主张、简短解释和进入 Creator 的行动入口。
- 右侧：两张用户价值卡片。
  - `面向理解`：动态变化、分步推导、公式与画面对应。
  - `面向创作`：先审查场景、保留 Manim 源码、按阶段修改。

## Copy rules

- 从用户任务、结果和决策角度表达，不使用“当前构建”“生产验证”“联调状态”等内部研发口吻。
- 不用 Queue、Sandbox、R2 或部署架构充当产品卖点；这些内容属于工程文档或可用性 FAQ。
- 不承诺数学自动正确。可以强调过程可检查，但不能写成结果已验证。
- CTA 指向 `/creator`，让用户从公式或教学目标开始实际体验。

## Style rules

- 使用 `curvg-stage curvg-frame`，延续首页边框、角标和留白体系。
- 卡片使用轻边框与低对比背景，视觉重点保持在价值标题和具体结果。
- 图标只帮助区分“理解”与“创作”，不能成为信息的唯一载体。

## Responsive behavior

- 桌面为价值说明与双卡片布局；小屏依次显示说明、理解价值、创作价值。
- 中文标题在小屏使用有语义的三行断句，避免自动换行拆散词组。
- 卡片标题保持短句，避免中文单字孤行。
