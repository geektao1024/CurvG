# CurvG 数学奇观（/wonders）规划

更新时间：2026-10-17

## 1. 定位：和实验室分开的第二种内容

总纲与学科边界见 `docs/POSITIONING.md`；选题必须过它第 2 节的规则。

|          | 实验室 `/labs`                    | 数学奇观 `/wonders`                            |
| -------- | --------------------------------- | ---------------------------------------------- |
| 回答什么 | 课本里的一个知识点怎样成立        | 一个"为什么会这样"的数学现象                   |
| 编排     | 学科 → 实验集 → 章节，跟课标走    | 按编号排的独立专题，不跟课标                   |
| 打开后   | 画板 + 引导步骤 + 讲解 + 随堂检测 | 先自动播一段带字幕的动画故事，再把参数交给读者 |
| 视觉     | 纸面与琥珀（浅色）                | 深色舞台：夜色底、发光线条、玻璃面板           |
| 去向     | 做成视频、相关章节                | 回到课本里的对应实验（`relatedLabs`）          |

参考：shapeof.world 的数学专题（实时场景 + "重播故事"），3Blue1Brown / Manim 的动画语法
（画出、叠加、镜头推近、聚焦）。不照搬它们的视觉资产和文案；shapeof.world 源码是 AGPL、
文案海报是 CC BY-NC，只能参考选题和交互，实现从公式出发自己写（见总纲第 6 节）。

## 3. 一个专题由什么组成

公共骨架（新专题不要再写一遍）：

- **舞台** `src/components/wonder-stage.tsx`（`WonderStage`）：画布（引擎要 WebGL 时下面多一层 WebGL 画布）、
  帧循环、故事时钟、字幕（带章节号）、节拍刻度、跳过/重播、全屏、参数面板外壳、安全区测量（标题/面板/字幕不压画面），
  以及面板小件 `WonderReadouts`、`WonderChips`、`WonderSlider`、`WonderToggle`。
  **电影模式**（2026-10-17，参考 shapeof.world 的呈现方式，自己实现）：故事播放时标题在第一拍后缩小、面板只留读数
  （`WonderReadouts` 之外的控件隐藏），画面接管腾出的空间；安全区按指数插值过渡，画面滑动而不跳切。进入自由模式后控件回来。
- **冷开场**（teaser）：引擎写 `teaser: [from, to]`（故事里 3–4 秒的高潮片段），页面一打开先播这一段（标题大字压在高潮画面上），
  再黑场切回第 0 秒讲故事；时钟从 `-teaserLength` 开始（`storyClock`、`teaserCut`，`engine.ts`）。重播与拖进度条不再放冷开场；
  导出的"整段故事"也以它开头（短视频前三秒决定留存）。
- **分享链接**：舞台的 `share={{ get, apply }}` 把自由模式的参数写进 `?s=k:v,…`（`src/lib/wonders/share.ts`，明文、限长、
  每个值由专题自己钳位）。带 `s` 打开页面时跳过故事，直接进入读者分享时的画面。底栏「复制分享链接」。
- **分享图**：底栏相机按钮生成 4:5（1080×1350）卡片：问题、当前画面（按画面安全区居中裁切）、一句话结论、网址。
- **下一个奇观**：故事播完的卡片下方推荐下一个（按编号循环）。
- **泛光** `src/lib/wonders/bloom.ts`：2D 层逐级缩小、小图上模糊、`lighter` 叠回。引擎用 `glow`（0–1）开启；
  只适合发光线条与粒子，WebGL 层不加。
- **导出** `src/components/wonder-export.tsx` + `src/lib/wonders/export.ts`：见第 4 节"读者导出"。
- **引擎契约** `src/lib/wonders/engine.ts`（`WonderEngine`）：`beats`、`length`、`frame(f, ctx)`、
  `leaveStory(t)`、`replay()`；可选 `glow`、`clone()`（带读者当前参数的新引擎，导出用）、
  `freeFilm()`（把克隆设成"我的版本"短片并返回秒数）；`safeArea()` 给出画面应居中的区域。
- **关键帧** `src/lib/wonders/timeline.ts`：`track` 缓动保持、`integrate` 由速度积分出角度、`easeSine` 等。

每个专题自己写四样：

1. **内容** `src/content/wonders/data/{slug}.ts`：问题（H1）、摘要、一句话结论、每个节拍一句字幕
   （同时是视频配音稿）、讲解小节（支持 `$…$`）、FAQ、相关实验、资料来源。
2. **数学 + 故事 + 引擎** `src/lib/wonders/{topic}.ts`：纯函数；故事是 `t` 的纯函数（需要模拟的预先算好，
   拖回去时从种子重算），引擎实现 `WonderEngine`。
3. **组件** `src/components/{topic}-wonder.tsx`：创建引擎，填参数面板。
4. **测试** `tests/wonders.test.ts`：文案里每个数字都有断言；故事节拍数 = 字幕条数；镜头不跳切。

搜索标题写在内容的 `metaTitle`（关键词在前，≤ 62 显示宽度，测试检查）；问题本身做 H1。
运行 `pnpm og:wonders` 生成分享图（测试检查文件存在）。

最后在 `-wonder-page.tsx` 的 `StageFor` 加一个分支、在 `wonder-poster.tsx` 加海报（从数学直接画，不用截图）、
在 `messages/{zh,en}.json` 加 `wonders.{topic}.*` 文案。

## 4. 视频

故事是 `t` 的纯函数，所以出片 = 逐帧采集同一个场景：`pnpm video:wonders [slug]`（`scripts/wonder-video.ts`，
帧源 `/render/wonder/$slug`，时间轴 `src/lib/wonders/film.ts`）。每个专题在数据里写 `film`（一拍一句旁白），
节拍按配音实测时长拉长，画面只放慢不停帧。视频走深色，出 16:9 + 9:16，产物在 `output/wonder-videos/`（不进 git）。

配音（2026-10-15 试音后定，ElevenLabs Starter，可商用）：

- 英文优先：库音色 Max – Elearning and Documentary（`Gfpl8Yo74Is0W6cPUWWT`），`eleven_multilingual_v2`，
  stability 0.5 / similarity 0.75 / style 0 / speed 1.05，前后句上下文拼接。约 140–150 词/分钟，
  对 8 个候选做过语速和转写检查。中文暂用 Alice + `eleven_v3`。
- 母带两遍 loudnorm 到 -14 LUFS / -1 dBTP（YouTube、TikTok、Instagram 的播放基准）。
- 改了旁白文案，只重新合成改动的句子（按音色、模型、参数、上下文缓存）。

### 读者导出（2026-10-17）

舞台底栏有「保存这一帧」（PNG：当前画面 + 角落 CurvG 标记与网址，免费不需登录）和「导出视频」。视频在读者浏览器里生成：
`engine.clone()` 得到一个不挂在页面上的引擎，画在离屏画布上，逐帧（不是录屏）经 WebCodecs 编码成 MP4
（Mediabunny，按需动态加载），所以导出的画面和页面完全一致，页面上的动画也不受影响。

- 内容：**整段故事**（故事模式，字幕按节拍淡入）或**我的版本**（自由模式、固定 `dt`，长度由 `freeFilm()` 决定）：
  傅里叶 1→2→4…翻倍到读者的圆数并描出读者的图形；曼德博从全貌按恒定的对数速度放大，正好停在读者的视图
  （全貌时改为潜入海马谷）；洛伦兹在两翼交界前放下一小团点（ρ=28 用故事里的释放点，其他 ρ 从几个候选里挑分离最快的）
  并让镜头慢慢环绕；向日葵按读者的角度一粒粒长出来。
- 版式：设计画布 1280×720 / 720×1280，按输出尺寸整体放大（笔画粗细与页面一致）；上方眉题+问题，下方字幕，最后 2.6 秒片尾卡
  （CurvG、一句话结论、网址）。
- 档位：免费 720p30（右下角水印 + 片尾，需登录）；高清 1080p60 无水印（片尾可选），下载时扣积分。码率固定（5 / 16 Mbps），
  分形不会把文件撑大。收费规则见 `MONETIZATION.md`。
- 测试：`tests/wonder-films.test.ts` 钉住"我的版本"的承诺。新专题要实现 `clone()` 与 `freeFilm()` 并在这里加一条断言。
- 浏览器不支持 WebCodecs 编码时（较旧的 Firefox）弹窗给出提示，不降级录屏。

摆波的故事不是匀速播放：`clockThrough()` 用三次 Hermite 曲线把故事时间映射到摆的时间，图案处放慢、图案之间快进，

质数螺旋的取景按数学定：第 m 族臂每向外 $2\pi m/|m-2\pi q|$ 个数绕一圈（6 族 133，44 族约 1.56 万，710 族 7400 万），
视野里只放一到两圈才认得出是"臂"，所以三幕分别在 150、5000、60 万（`armTurnRadius()`，测试钉住）。按余数上色时画出
臂的引导线（n, n+m, n+2m…），只看质数时和模数不互质的空臂连同引导线一起淡出。

牛顿分形把多项式写成根的列表，一步牛顿法 $z\to z-1/\sum 1/(z-r_k)$，所以读者能直接拖动根、增删根。着色器在一个像素的 4 个
子采样落到不同的根时把它画成白线，即边界本身；地盘内部按步数做暗到中等亮度的等步环。单精度限制最深到视野宽 0.0002。
分享链接里自定义的根写成 `0.3j-0.8`（不用 `+`，查询串会把它读成空格）。

#### 8. 高尔顿板（`galton-board`）— 已上线 2026-10-17

- **问题**：每颗小球左右乱撞，为什么落下来总是一座钟形的山？
- **数学**：n 排钉子，每次左右各 1/2，落在第 k 格的概率是 $\binom{n}{k}/2^n$（数路径就是杨辉三角）；n 大时趋于正态分布，
  均值 $n/2$、标准差 $\sqrt n/2$（中心极限定理）。12 排时正中一格有 924 条路径，占 22.6%；最边上只有 1 条。
- **故事**：一颗球的路径（每颗钉子一次抛硬币）→ 钉子上标出杨辉三角的路径数 → 放下两千颗球，柱子长成二项分布，
  叠上理论曲线 → 排数加多变成正态曲线 → 把板子倾斜（p ≠ 1/2）钟形平移但还是钟形 → 为什么：许多独立的小偏差相加 →
  轮到你。
- **确定性**：故事里第 i 颗球的每一次左右由 (i, 排) 的种子哈希决定，球的位置是时间的纯函数，拖回去也一样。
- **画面**：发光的钉阵、带短拖尾的小球弹跳、底部按格堆起的小球柱，理论曲线描青色。
- **交互**：排数、倾斜概率 p、下落速度、"再放一千颗"、显示杨辉三角、显示理论曲线。
- **我的版本**：读者的排数与 p，十几秒放下约一千五百颗球，最后叠上理论曲线。
- **实际做法与改动**：
  - 故事分四批球（单球 / 12 排两千颗 / 24 排两千颗 / 倾斜 p = 0.7），每批是 `Batch`，球 i 的第 r 次拐弯由
    `hash01(seed, i, r)` 决定，位置是时间的纯函数；自由模式是实时模拟（不需要可重放）。
  - 读数在故事里也显示"实测 / 理论"，取自引擎 `shown`（画在板上的那批），故事和自由模式同一套。
  - 文案改正：初稿写"两千颗球实测和理论差不到 1 个百分点"，实测 24 排有一格差 1.7 个百分点；改为"每一格都不到 2 个百分点"，测试钉住。
  - 修过的 bug：柱高按 `max(1, …)` 归一化，概率都小于 1，柱子被压扁成矮条；改为 `max(1e-9, …)`。

#### 9. 布丰投针（`buffon-needle`）— 已上线 2026-10-17

- **问题**：往画着平行线的地板上随手扔针，为什么能算出 π？
- **数学**：针长 l ≤ 线距 d 时，压线概率 $2l/(\pi d)$；l = d 时约 63.66%，于是 $\pi\approx 2N/C$。误差约按 $1/\sqrt N$ 缩小，
  所以很慢。漂亮的解释是"布丰面条"：任何形状的针，平均压线次数只和长度成正比；把针弯成直径为 d 的圆，每次都恰好压线 2 次，
  周长 πd，比例常数就出来了。
- **故事**：扔针（压线的变色）→ 估计值曲线在 π 附近抖动、慢慢收窄 → 为什么慢（1/√N 漏斗）→ 面条与圆环的证明 →
  拉扎里尼 1901 年 3408 针得出 355/113 的"好运气" → 轮到你。
- **交互**：针长比例、扔针速度、一次扔一千根、换成弯针/圆环。
- **我的版本**：读者的针长，18 秒里按对数节奏扔到三万根，估计值曲线和 ±2σ 漏斗一起走。
- **实际做法与改动**：
  - 针 i 的位置和角度由 `hash01(seed, i, ·)` 决定，压线计数按 (seed, 针长) 缓存前缀和，故事里一万根针总是得到 3.1546（测试钉住）。
  - 面条（随机弯曲、长度 2.4 倍线距）与圆环（直径 = 线距）都是真算交点：两万根面条每单位长度平均压线 0.634 次（2/π = 0.637），
    圆环永远 2 次，测试都在核对。
  - 拉扎里尼一幕原计划只说"好运气"，查证后改为可核对的说法：恰好 1808 根压线的概率约 1.4%（二项分布精确计算），
    3408 = 16 × 213 恰好能凑出 355/113，多半是挑了停手时机。
  - 改过的地方：三行字幕会挡住估计曲线，曲线上移、两条长字幕压短；面条初版卷成线团，降低弯曲幅度。

#### 10. Collatz 树（`collatz-tree`）— 已上线 2026-10-17

- **问题**：偶数除以 2、奇数乘 3 加 1，为什么每个数最后都掉到 1？——至今没人能证明。
- **数学**：27 要走 111 步，最高冲到 9232；已经用计算机验证到很大的数但没有证明。把每个数回到 1 的路径反过来画，
  偶数步向一侧小转、奇数步向另一侧转，就长成一株珊瑚（Edmund Harriss 的画法思路，自己实现）。
- **故事**：27 的冰雹曲线 → 很多数的步数 → 路径倒过来画成树 → 树越长越茂密 → 为什么难（平均每次奇数步再除以 2 是 ×3/4，
  看起来会变小，但"平均"不是证明）→ 轮到你。
- **交互**：转角参数、画到多少个数、按步数上色、输入一个数看它的路径。
- **我的版本**：读者的转角与数量，珊瑚从根 1 按深度一层层长出来（15 秒）。
- **实际做法与改动**：
  - 树按"每个数一个节点、父节点 = 下一步"建成（1 到 1 万共 21664 个节点，最深 261），每条边只画一次；边按（深度 × 粗细档）
    预先合成 `Path2D`（世界坐标），每帧只做缩放和按深度裁剪，所以三万个数也能流畅生长。粗细按经过的数的多少分三档。
  - 故事三种画法：6 与 27 的冰雹曲线 → 1 到 1 万的步数散点 → 1 到 100 的小树（27 的路描白，随生长逐段出现）→ 整株珊瑚。
  - 改过的地方：27 的白线初版要等树长满才出现；小树初版只有 1 到 30，太稀；拖动转角会让树反复重长，改为只有改数量时才重长；
    中文问题缩短，避免分享图里"最/后"断行。
  - 已核对的说法：验证到 2⁶⁸（Barina，J. Supercomputing 2021）、陶哲轩 2019 "几乎所有轨道"（arXiv:1909.03562），来源已列在页面。

#### 11. 奇异吸引子画廊（`strange-attractors`）— 已上线 2026-10-17

- **问题**：两行公式、四个数，为什么能画出这样的图？
- **数学**：Clifford 映射 $x'=\sin(ay)+c\cos(ax)$，$y'=\sin(bx)+d\cos(by)$。迭代几百万次后点的密度就是画面；
  李雅普诺夫指数大于 0 才是"奇异"吸引子，小于 0 时只剩几个点（周期轨道）。和洛伦兹不是同一意图：那边讲"确定却不可预测"，
  这边讲"参数空间里哪里有画"。
- **故事**：一个点来回跳 → 点越积越多显出图形 → 参数慢慢变，画面连续变形 → 有些参数只剩几个点（指数 < 0）→ 画廊 → 轮到你。
- **交互**：四个参数滑块、随机找一幅（只接受指数 > 0 的）、配色。
- **我的版本**（改了计划）：读者的画从几个点开始一点点显现，16 秒内积累到六百万个点。
- **实际做法与改动**：
  - 每帧把新增的点累加进一张按像素计数的密度表，对数色调映射（查表），密度没变时不重算；停手后画面继续变细。
  - **为什么不做参数漂移**：扫描发现混沌区里到处夹着很窄的周期窗口（例如 c 方向在 0.704、0.76、1.07 附近），
    参数一漂进去点就塌成几个，画面会闪。所以故事第 5 幕只沿 d ∈ [0.58, 1.25] 变形：这一段事先逐点扫过、没有周期窗口
    （测试每 0.1 秒检查 λ > 0）；画廊改为淡入淡出切换，不再在两幅之间插值；"我的版本"改为点一点点显现，不再漂移参数。
  - a 从 −1.4 滑到 −0.95 落入 3 点循环（λ ≈ −0.21），测试核对循环点数 = 3。"随机一幅"只接受 λ > 0.1 且 64×64 格里覆盖 ≥ 400 格的组合。
  - 李雅普诺夫指数只在浏览器里算：混沌会把服务器和浏览器 sin/cos 末位的差别放大，服务端渲染出的读数会和浏览器不一致（hydration 报错）。
  - 英文搜索标题初稿 67 宽超限，改为 "Strange Attractors: Art From Two Lines of Math"。
