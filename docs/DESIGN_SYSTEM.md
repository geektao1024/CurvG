# CurvG 设计指南 —— 精密数学画框

公开页面的关键词映射、内容语气和能力声明边界以 `docs/SEO_CONTENT_STRATEGY.md` 为准；视觉规范不得通过“99.9% 精度”、未上线格式或虚构用户数据制造可信感。

> **状态：当前首页的唯一设计真相来源。**
> 更新日期：2026-07-24。适用范围：`/` 首页及复用其视觉语言的公开营销页面。
> 本文替代旧版“黑板宇宙”方向；旧方向与现有浅色画框、Space Grotesk 排版、靛蓝像素交互实现冲突，不得继续沿用。

## 1. 设计定位与借鉴边界

### 已落实的定位

CurvG 是一个把数学公式转为可检查动画的产品。首页应呈现为一张**精密的数学工作画布**：冰白底、细边框、坐标网格、公式读数和实时曲线共同建立可信度；靛蓝用于操作与数学重点。

### 参考来源

首页的画框、排版密度、像素揭示和扰码交互参考 `ragnarok.framer.ai` 的已验证行为。原始拆解记录在：

- `docs/research/ragnarok.framer.ai/DESIGN_TOKENS.md`
- `docs/research/ragnarok.framer.ai/PAGE_TOPOLOGY.md`
- `docs/research/ragnarok.framer.ai/BEHAVIORS.md`
- `docs/research/components/ragnarok-*.md`

### 必须保留的 CurvG 差异

- 首页主视觉是公式、坐标与 `LivingCurve`，**不是**竞品的 AI Agent 流程 Hub。
- 文案、Logo、曲线公式和产品状态必须属于 CurvG；不能复制竞品品牌资产、产品叙事或 AI 工作流内容。
- 交互复制的是机制（像素揭示、扰码、双箭头轨道），不是竞品代码和位图资源。
- 对未上线的能力如 AI 场景生成、Sandbox 渲染、视频导出，使用“planned / next phase”等真实表述；禁止把计划写成已可用功能。

## 2. 视觉原则

1. **先建立坐标系，再放内容。** 页面层次由边界、网格、细点阵和留白建立，不靠大阴影或大面积渐变。
2. **数学动画是唯一主角。** Hero 同一视口只保留一条持续动态的 `LivingCurve`；视频样片默认显示静态海报，只允许当前悬停、聚焦或点击的卡片播放，禁止六段样片同时自动运行。
3. **交互使用低分辨率语言。** CTA 箭头、像素格揭示和文字扰码构成统一的“计算过程”隐喻；不使用泛滥的发光、漂浮或视差。
4. **框架克制、内容明确。** 常规导航、常规 FAQ、常规链接和可读文本优先；微动效只在提示状态变化或计算过程时出现。

## 4. 画框与背景层级

### 4.1 页面骨架

- 主画框：`.curvg-stage`，宽度 `min(1360px, calc(100% - 80px))`，水平居中。
- 左右侧轨：在最大画框外各保留 `40px`；使用 `135deg`、`4px` 周期的低对比斜线纹理，并有 `1px` 边线。
- 画框边界：`.curvg-frame` 使用左右 `1px solid var(--border)`；区块之间优先使用水平 `1px` 边线或 `.curvg-dotted-divider`，不要用厚阴影分区。
- 侧轨、网格、点阵和角标是装饰层，必须 `pointer-events: none`，不能覆盖真实链接或按钮。
- 小于 `768px` 时隐藏侧轨，`.curvg-stage` 改为满宽；内容本身的 `px-6` / `sm:px-10` 承担移动端边距。

### 4.2 背景叠放顺序

1. `#f3f3f9` 页面底色。
2. 顶部极淡的靛蓝径向光晕（仅 `2.8%` primary 混色），不能扩大成彩色背景。
3. 固定左右斜线侧轨。
4. 主画框的 `1px` 边界与分栏线。
5. 局部坐标网格：`32px × 32px`，前景色约 `5.5%` 混色。
6. 局部点阵：靛蓝 `1px` 点、`14px × 14px` 间距，以径向 mask 渐隐。
7. 内容、曲线和可交互控件。

`curvg-section-field` 仅用于需要额外数学氛围的白色区块：其左右两侧各有旋转的低密度点阵，不要给每一个小组件重复添加。

### 4.3 角落定位标记

- 统一使用 `public/corner-marker.svg`，尺寸 `15px × 15px`。
- `.curvg-corner` 以 `5s linear infinite` 旋转一整圈。
- Hero 只放顶部两个；普通内容区块通常放顶部两个；深色 CTA 放四个角。
- `prefers-reduced-motion: reduce` 时停止旋转，保留静态图形。

## 5. 首页信息架构

首页顺序固定为：

1. `Header`：80px 画框导航。
2. `Hero`：左侧叙事与 CTA，桌面右侧数学画布；下方四格能力状态条。
3. `FormulaWorkspacePreview`：公式、场景规格与可检查预览的静态产品示意；明确不触发当前尚未上线的生成或渲染。
4. `CurveGallery`：六张真实 Manim 成片样片卡，覆盖文字、绘图、数列、数据、三维几何与轨道运动。
5. `Features`：三步可检查的目标工作流卡片。
6. `UseCases`：教育工作者、学习者、课程与视频创作者的任务场景；不伪造客户或社区数据。
7. `BuildStatus`：将当前可见能力与后续基础设施里程碑明确分开。
8. `FAQ`：常规单项展开问答。
9. `CTA`：唯一大面积深色高潮区。
10. `Footer`：回到浅色画框与多列链接。

首页装配入口是 `src/routes/index.tsx`。新增首页区块前，先判断它是否属于上述叙事；若只是重复功能说明，优先扩展现有区块而不是再加一屏。

## 6. Header 与 Hero

### 6.1 Header

- 高度 `80px`，使用 `.curvg-stage.curvg-frame`，不 sticky；正常随页面滚出视口。
- 品牌 Logo `32px`、圆角 `8px`，品牌名采用 `18px semibold`。
- 桌面导航只在 `md` 及以上显示；移动端为常规菜单按钮和纵向菜单，不依赖 hover。
- 语言与主题控制器、右侧 `Create` 入口用 `1px` 分隔线隔开。

### 6.2 Hero 布局

- 桌面（`lg` 及以上）最小高度 `600px`，左右各 `50%`，中间 `1px` 分栏线。
- 左侧内容：`px-10`；移动端为 `px-6 py-16`，文字在上、曲线在下。
- 右侧内容：坐标网格 + 点阵 + `LivingCurve` + 图注 / 精度 / 公式读数。保留 CurvG 的数学画布，不替换成 AI 流程节点。
- `lg` 以下隐藏右侧分栏，并在文案下展示 `300px`（`sm: 360px`）高的曲线画布。
- 底部状态条：手机单列、`sm` 两列、`lg` 四列；使用细边线分隔，不使用圆角卡片。

### 6.3 Hero 文案约束

Hero 标题必须保持**三段结构**，由 `src/blocks/hero.tsx` 的三个块级 `span` 约束：

1. 固定首行：产品的输入或起点。
2. 动态靛蓝中行：三个短语循环打字。
3. 固定末行：产品结果或价值收束。

英文基准：`Turn equations into` / 动态短语 / `Frame by frame.`。中文翻译保持同样三段语义，不要依赖浏览器自动换行来凑成三行。

- 打字速度 `62ms/字符`，删除 `34ms/字符`，完整词组停留 `1800ms`。
- 光标宽 `0.08em`，`0.8s steps(1)` 闪烁。
- 动态短语在 `sm` 及以上不换行；在窄屏允许自然换行以避免溢出。
- 副标题最大宽度 `28rem`。英文和中文应在 `960px` 亮色视口下各占 **2 行**；修改文案后必须实际验证，不能只按字符数估算。
- 主 CTA 与次级链接间距 `20px`；次级链接只使用文字、下划线与前景色变化。

## 7. 按钮、导航与像素交互

所有以下交互由 `src/components/pixel-reveal-link.tsx` 与 `src/components/pixel-arrow.tsx` 提供。触发条件统一为 hover、键盘 `focus-visible` 或按下状态；离开后恢复默认。动效必须在 `prefers-reduced-motion: reduce` 下退化为稳定状态。

### 7.1 Hero 主 CTA：`variant="primary"`

| 属性     | 规则                                                                                 |
| -------- | ------------------------------------------------------------------------------------ |
| 默认尺寸 | 最小高 `53px`，内边距 `14px 16px`                                                    |
| 默认外观 | `#201f32` 背景、白字、`5px` 圆角、18px / 25.2px Inter                                |
| 揭示层   | `5 × 2` 硬边像素格，蓝底 `#262ef2`，深色格 `#201f32`                                 |
| 揭示顺序 | 从右向左，每格约 `45ms`，总约 `450ms`；两行顺序可随机                                |
| 文本     | 原文 `600ms cubic-bezier(.44,0,.56,1)` 淡出；6 字符扰码带从左向右，每 `32ms` 更新    |
| 噪点颜色 | 白色文本上的扰码为 `rgba(255,255,255,.5)`                                            |
| 箭头     | `16px` 裁切窗口内并排两份 `5 × 5` 像素箭头；hover 显示前一份，轨道与变体同为 `600ms` |

CTA 本体不旋转，也不应常驻噪点层。

### 7.2 导航普通入口：`variant="nav-item"`

- 最小高 `38px`，内边距 `11px 10px`，圆角 `4px`，`16px / 16px` Inter。
- 默认透明；激活时背景为 `rgba(31,31,50,.05)`。
- **只有**左到右的 6 字符扰码，不使用像素格揭示或箭头。
- 扰码色 `#a1a1a1`，背景过渡使用约 `400ms` 的弹性曲线。
- 适用于 `Create`、`Gallery`、`Workflow`、`FAQ` 等桌面文本导航。

### 7.3 导航 CTA：`variant="navigation"`

- 最小高 `38px`，内边距 `8px 10px`，`5px` 圆角。
- 默认 `#f3f3f9` 背景、`1px #e3e2e5` 边框、`#201f32` 文字。
- Hover 使用 `2 × 1` 像素格，从右到左、总约 `450ms`，最终显白色底。
- 文字扰码规则与普通导航相同；不显示像素箭头。

### 7.4 深色 CTA 区的浅色按钮

深色 CTA 区使用浅色主按钮和 `PixelArrowRail`，可切换双箭头轨道；不要把 Hero 的蓝色 5×2 像素揭示强行复制到该按钮，除非对应组件也改为 `PixelRevealLink` 并完成动效验证。

### 7.5 焦点与可访问性

- 所有 `PixelRevealLink` 的 `focus-visible` 使用 `2px #262ef2` 描边和 `3px` offset。
- 扰码层是视觉层，真实链接必须保留可访问名称。
- 箭头、像素格和装饰图形一律 `aria-hidden`。

## 8. 曲线、点阵与卡片

### 8.1 `LivingCurve`

- 首页使用 `renderStyle="hairline"`：`1px` 靛蓝曲线、虚线十字准星、跟随点和等宽坐标读数。
- 曲线由 480 个采样点绘制，在利萨茹、玫瑰、蝶形、内摆线四个形态间循环；每个形态周期 `9s`，末 `30%` 使用平滑插值过渡。
- 指针在画布内移动时可产生局部数学形变；离开后回到原曲线。
- `prefers-reduced-motion: reduce` 固定在静态时间截面，不再 requestAnimationFrame 循环。
- 该画布是产品相关演示，必须保留坐标、公式或图注等解释性信息，不能退化成纯装饰线条。

### 8.2 视频样片卡片与工作流卡片

- 卡片表面：白色、`1px` 边框、`8px` 圆角；不要使用厚边、玻璃模糊或持续阴影。
- hover 最多上移 `2px`，边框轻微偏靛蓝；阴影仅为低对比扩散阴影。
- 指针进入时，`InteractiveSurface` 在指针坐标绘制半径 `240px`、约 `9%` primary 混色的径向光晕，`180ms` 淡入；离开后消失。
- 视频样片卡使用真实 `1080p / 60fps` H.264 成片与对应静态海报；画面旁必须保留类别、时长、序号和场景表达，不能退化成无说明的视频墙。
- 默认不自动播放全部样片：桌面悬停或键盘聚焦播放，离开后暂停；触屏设备通过明确的播放按钮控制。卡片离开视口后必须暂停。
- 每张卡只提供一项播放控制，不增加时间轴、音量或全屏控件；当前六段素材均无音轨，保持 `muted`、`playsInline` 和循环预览。
- `prefers-reduced-motion: reduce` 时关闭指针光晕和卡片位移。

### 8.3 深色 CTA

- 这是首页唯一允许的大面积深色区域：`#201f32` 背景、`#f3f3f9` 文字。
- 容器可用 `16px` 圆角（`rounded-2xl`）；它是强调模块，不是全站卡片圆角标准。
- 背景网格为白色 `4%` 透明度、`32px` 间距，并用径向 mask 渐隐。

## 9. 其他区块规范

### Gallery / Workflow

- 区块使用居中的等宽章节标记：低对比 `‹‹` / `››`、一个靛蓝图标和中间标题。
- 内容区块常用 `px-6 py-20`，`sm:px-10 sm:py-28`。
- Gallery 使用 `md` 两列；Workflow 使用 `lg` 三列。
- 仅功能区块使用侧边点阵；FAQ 保持清洁，避免制造视觉噪音。

### FAQ

- 使用正常单项 Accordion，不做卡片堆叠或复杂展开动画。
- 问题为 `16px semibold`，上下 `24px`；答案为次级文字、舒适行距。
- FAQ 是事实澄清区，答案必须与产品实际状态一致。

### Footer

- 回到浅色画框体系，使用多列链接、语言选择器与底部版权行。
- 链接只用前景色变化，不应加入像素揭示、上移或大阴影。

## 10. 响应式规则

| 断点           | 必须发生的变化                                                            |
| -------------- | ------------------------------------------------------------------------- |
| `<768px`       | 隐藏侧轨；画框满宽；区块点阵缩小；移动导航改为菜单；Hero 曲线移到文案下方 |
| `sm`（640px）  | Hero 动态短语保持单行；状态条两列；副标题可使用 18px                      |
| `md`（768px）  | 显示桌面导航；Gallery 两列                                                |
| `lg`（1024px） | Hero 恢复 50/50 分栏和右侧曲线；状态条四列；Workflow 三列                 |

不要为了桌面截图而固定绝对宽度。Hero 动态短语在窄屏可换行，但桌面基准必须保持三段标题结构。

## 11. 减少动态与性能

- 所有时间驱动动效都必须支持 `prefers-reduced-motion: reduce`：打字机显示首个词、角标停止、像素格即时隐藏、扰码不显示、指针光晕关闭、曲线静止。
- 视频样片使用 WebP 海报和 `preload="metadata"`；减少动态模式下不因 hover / focus 自动播放，用户仍可通过播放按钮主动观看。
- 画布使用 `ResizeObserver`，像素比上限为 `2`；新增曲线效果不得提高采样点或增加额外 canvas，除非先完成性能测量。
- 装饰层绝不接收指针事件，避免干扰导航、CTA 和曲线画布本身。

## 13. 后续改动流程与验收

### 修改前

1. 先检查本指南与对应的 `docs/research/components/ragnarok-*.md`。
2. 需要改变视觉规则时，先更新本指南，再改代码；研究记录是证据，`DESIGN_SYSTEM.md` 是最终规范。
3. 修改可见文案时，同步更新 `messages/en.json` 和 `messages/zh.json`；组件不直接硬编码双语内容。

### 修改后最小验收

1. 运行 `pnpm build`。
2. 在亮色主题检查 `1440px`、`960px` 和 `390px`：侧轨、画框、导航、Hero、卡片栅格、CTA 与 Footer 不溢出。
3. 在 `960px` 检查 Hero：标题为 3 行，副标题为 2 行，CTA 没有被曲线画布覆盖。
4. 检查 Hero CTA、普通导航和导航 CTA：触发条件、像素格数量、扰码和箭头行为符合第 7 节。
5. 打开 reduced-motion：无持续旋转、无扰码、无卡片光晕或位移，视频不因 hover / focus 自动播放，但播放按钮仍可完整使用。
6. 新增视觉资产必须服务数学解释或操作反馈；不满足这一点的动效、噪点、浮动光球和视差一律不加。

## 14. 禁止项

- 不恢复旧版墨绿黑板、Libre Baskerville、粉笔线或“全站深色正典”规则。
- 不把竞品的 AI Agent Hub、流程节点文案或品牌图形迁入 CurvG。
- 不在普通导航、Footer 链接或所有卡片上泛用 Pixel Grid Reveal。
- 不使用大面积玻璃模糊、沉重投影、持续漂浮、无因果的粒子或彩色渐变背景。
- 不将未验证的竞品行为写为事实；无法复现时在研究文档标注“待验证”，不要污染本规范。
