# CurvG 设计系统 —— 天文馆方案

> 本文档是全站前端样式与交互的唯一真相来源。所有 UI 决策以此为准。
> 决策过程：苏格拉底式需求澄清（2026-07），四个根问题的答案锁定了整套哲学。
> 关联文档：`SITE_ARCHITECTURE_PLAN.md`（信息架构）、`ROADMAP.md`（执行优先级）

---

## 一、设计哲学（四个已锁定的根决策）

| 根问题           | 决策                                  | 含义                                                  |
| ---------------- | ------------------------------------- | ----------------------------------------------------- |
| 3 秒内的核心情绪 | **敬畏——数学之美**                    | 深色天文馆底色，数学是主角，界面隐入黑暗              |
| 唯一的签名交互   | **曲线活在界面里**                    | 一条 WebGL 实时曲线是整站的灵魂资产                   |
| 动效的本质作用   | **解释因果**                          | 动效只用于状态转换、空间关系、注意力引导；零装饰动效  |
| 愿付出的代价     | **性能预算 + 信息密度**（天文馆方案） | 允许 WebGL 常驻；大留白、每屏一件事；骨架保持完全常规 |

### 一句话概括

> **整站像一座天文馆：黑暗、安静、克制，唯一的光是那条活着的曲线。个性 100% 压在曲线上，骨架 100% 常规易用。**

### 三条不可违背的红线

1. **只有一个主角**：任何页面同时只能有一条"活的曲线"。两条曲线互相抢戏 = 违规。
2. **动效必须有信息量**：每个动效必须能回答"它解释了什么因果"。回答不了就删。
3. **骨架不许实验**：导航、表单、按钮、布局全部遵循最常规的模式。用户的学习成本必须为零。

## 二、色彩系统

### 主题策略

**跟随系统 + 默认深色**：首次访问强制深色（保证第一印象），之后尊重系统偏好并允许手动切换。深色是"正典"，浅色是"适配"。

### 深色主题（正典）

总共 5 个颜色角色（严格遵守 3-5 色原则）：

| Token                  | 值（参考）                           | 角色                                                     |
| ---------------------- | ------------------------------------ | -------------------------------------------------------- |
| `--background`         | `#0A0E1A`（近黑的深蓝，非纯黑）      | 天文馆穹顶。纯黑 `#000` 太死，深蓝黑有空间纵深感         |
| `--foreground`         | `#E8ECF4`（冷调off-white）           | 正文。对比度 ≥ 13:1                                      |
| `--primary`            | `#3B9EFF → #22D3EE` 光谱（电磁蓝青） | 唯一主色：曲线本体、链接、焦点态、主按钮                 |
| `--muted` / `--border` | `#1A2236` / `#232D47`                | 卡片底、分隔线。比背景亮一档，不用纯灰                   |
| `--accent`（慎用）     | `#FFB454`（暖琥珀）                  | 仅用于"审批/确认"等关键决策时刻的强调，全站出现频率 < 5% |

### 曲线发光规格（签名资产）

- 曲线本体：`--primary` 蓝青，线宽 2px（桌面）/ 1.5px（移动）
- 发光：两层——内层 `blur 4px` 同色 60% 透明度，外层 `blur 16px` 同色 20% 透明度
- 发光只属于曲线。按钮、卡片、文字一律不发光，否则稀释签名资产
- 实现：WebGL 中用加色混合（additive blending）；SVG 降级用 `filter: drop-shadow` 两层叠加

### 浅色主题（适配）

浅色下"发光"物理上不成立，视觉语言切换为**"墨水"隐喻**：

- `--background`: `#FAFBFD`，`--foreground`: `#0F1629`
- 曲线：同一蓝青色但去掉发光，加粗到 2.5px，像精密绘图笔的墨迹
- 其余 token 对应翻转，`--accent` 保持琥珀不变

## 三、字体系统

严格 2 个字族：

| 用途        | 字体           | 说明                                                                                  |
| ----------- | -------------- | ------------------------------------------------------------------------------------- |
| 标题 + 正文 | **Geist Sans** | 冷静、精密、国际化。标题用 `font-medium`（500），拒绝超粗字重——敬畏感来自留白而非音量 |
| 数学/代码   | **Geist Mono** | 行内公式记号、代码块、参数值。LaTeX 公式本身由 KaTeX 渲染（其自带字体不计入字族预算） |

排版规则：

- 正文 `leading-relaxed`（1.625），最小 14px
- 首屏标题克制：`text-4xl md:text-6xl`，不用 `text-8xl+` 的嘶吼式排版
- 标题一律 `text-balance`，正文段落 `text-pretty`
- 中文场景：Geist 回退到系统中文字体栈，字重和字号规则不变

## 四、布局与空间原则

- **每屏一件事**：营销页每个 section 只讲一个论点。低信息密度是刻意选择的代价
- **垂直节奏**：section 间距 `py-24 md:py-32`；内容最大宽度 `max-w-5xl`，长文（百科/博客）`max-w-2xl`
- **Flexbox 优先**，复杂二维布局才用 Grid；禁止绝对定位堆砌（唯一例外：曲线画布固定层）
- **移动优先**：所有布局从 375px 开始设计，向上增强

## 五、签名交互："活的曲线" 完整规格

这是倾注 80% 打磨精力的地方。分四级实现，逐级降级：

### L1 首页主角曲线（最高优先级）

- 一条全屏 WebGL 曲线（Canvas 固定层，`position: fixed`，z-index 在内容之下）
- **随滚动演化形态**：滚动进度驱动曲线在数学形态间连续插值——例如 正弦波 → 利萨茹图形 → 心脏线 → 傅里叶方形波逼近。每个形态对应一个 section 的叙事（这就是"动效解释因果"：滚到"傅里叶"章节，曲线就变成傅里叶）
- 形态切换用参数空间插值（同一参数方程族的系数渐变），不是透明度淡入淡出
- 鼠标不扰动曲线（扰动是装饰性的，无因果信息，违反红线 2）

### L2 过程即曲线（工作台）

- Creator 渲染排队/进行中：进度条就是"正在被绘制的曲线"——从左到右按真实进度绘制当前作品的缩略曲线。等待本身传达"你的数学正在成形"
- 规格审批通过时：一次性的曲线"点亮"脉冲（发光强度 0.2s 内提升后回落）——这是全站唯一允许的庆祝动效，因为它标记了状态机的关键跃迁

### L3 百科页的活标本

- 每个 `/curves/[slug]` 页首是该曲线的交互式版本：拖动参数滑块，曲线实时重算。这不是装饰，是百科的核心内容
- 参数变化时公式中对应的系数同步高亮（因果链接：滑块 → 系数 → 形状）

### L4 降级策略

- `prefers-reduced-motion`：曲线渲染为静态 SVG 最终形态，滚动演化关闭
- 低端设备（检测 `devicePixelRatio` + 首帧耗时 > 33ms）：WebGL 降级为预计算的 SVG 路径序列
- 无 JS / 爬虫：服务端内联静态 SVG，SEO 页面内容完整可索引

## 六、动效准则（解释因果）

| 场景                                    | 动效                             | 时长      |
| --------------------------------------- | -------------------------------- | --------- |
| 页面导航切换                            | 无过渡（速度即尊重）             | 0         |
| 状态机跃迁（draft→spec→code→rendering） | 阶段指示器沿路径推进             | 300ms     |
| 展开/折叠（规格分镜、代码块）           | 高度 + 透明度                    | 200ms     |
| 焦点/悬停                               | 颜色/边框即时变化                | 100-150ms |
| 曲线形态演化                            | 滚动驱动（无固定时长，跟手）     | —         |
| 审批通过                                | 曲线点亮脉冲（全站唯一庆祝动效） | 200ms     |

禁止清单：背景粒子、呼吸光效、悬浮微动、视差装饰、打字机效果、骨架屏闪光之外的加载动画。

## 七、各页面设计方向

| 页面                  | 设计要点                                                                                      |
| --------------------- | --------------------------------------------------------------------------------------------- |
| `/` 首页              | L1 主角曲线 + 每屏一论点。首屏只有：一句价值主张、一个 CTA、那条曲线                          |
| `/creator` 工作台     | 三栏骨架完全常规（对话流 / 规格审阅 / 预览）。深色底让用户的数学内容成为唯一亮点。L2 过程曲线 |
| `/curves/[slug]` 百科 | L3 活标本置顶，正文 `max-w-2xl` 浅色适配阅读优化，KaTeX 公式块与正文同宽                      |
| `/gallery` 画廊       | 深色底 + 视频缩略图网格，缩略图自发光（视频内容本身是亮的），卡片零装饰                       |
| `/pricing` `/blog`    | 完全常规骨架，靠排版与克制配色维持气质，不放活曲线（红线 1：这些页面没有主角资格）            |

## 八、实现注意事项

- 现有 `src/styles/globals.css` 为 Tailwind 入口；主题 token 以 CSS 变量定义，深浅色通过 `class` 策略切换，`<html>` 挂 `bg-background`
- 首次访问深色默认：内联脚本在 hydration 前写入主题 class，避免闪白（FOUC 对"天文馆第一印象"是致命的）
- WebGL 曲线组件应为独立模块（建议 `src/components/living-curve/`），带明确的 props 契约（形态序列、滚动绑定、降级开关），供 L1-L3 复用
- 性能预算：曲线渲染 ≤ 4ms/帧（60fps 下留 12ms 给其余渲染）；首屏 LCP 不因 WebGL 恶化——曲线延迟到 LCP 元素绘制后初始化

## 九、验收标准

1. 用户打开首页 3 秒内，视线焦点必然落在那条曲线上（唯一发光体）
2. 全站任意页面截图拼在一起，配色/字体/间距完全一致
3. `prefers-reduced-motion` 用户获得完整功能与完整内容
4. Lighthouse 移动端 Performance ≥ 90（含 WebGL 页面，降级生效）
5. 任何新增动效都能在 code review 中回答"它解释了什么因果"
